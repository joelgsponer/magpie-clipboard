## session: leader-switcher reframe (⌘Space cockpit)

- Branch `leader-switcher` reframes Magpie as a macOS cockpit: ⌘Space opens a
  tool chooser (weapon-wheel HUD), letter picks the tool. New tools: Apps (A),
  Search (S), Math (M). Code in `Sources/Magpie/Cockpit/`, `Launcher/`,
  `Spotlight/`, `Calculator/`.
- GOTCHA: a Carbon hotkey on ⌘Space silently loses to Spotlight. A CGEvent tap
  at `.cghidEventTap` + `.headInsertEventTap` that returns nil for ⌘Space DOES
  beat Spotlight (verified 2026-09-09). Needs Accessibility trust.
- GOTCHA: a `.nonactivatingPanel` that is made key loses key status to the
  frontmost app within ~150 ms when that app is Chrome (Alacritty leaves it
  alone). Don't build modal keyboard UI on key-window status; the chooser
  routes key-downs through the same event tap (`LeaderKey.keyInterceptor`).
- GOTCHA: `NSMetadataQueryIndexedLocalComputerScope` gathers 0 results here;
  `NSMetadataQueryLocalComputerScope` returns the full index.
- GOTCHA: `/Applications/Safari.app` is a *hidden* symlink into
  `/System/Cryptexes/App/System/Applications/`; `skipsHiddenFiles` drops it, so
  the cryptex path is a scan root of its own.
- GOTCHA: `log show --predicate 'process == "Magpie"'` shows nothing for NSLog
  output. To see Magpie's logs, run `Magpie.app/Contents/MacOS/Magpie` from a
  terminal and read stderr.
- PROCEDURE: keyboard-level testing without a human: a tiny Swift helper that
  posts CGEvents (`cmdspace`, letters, `type:<string>` as one unicode event)
  and lists on-screen windows via `CGWindowListCopyWindowInfo`, then
  `screencapture -l <windowID>`. Posting one char per event lost every char
  after the first; one event carrying the whole string works. Synthetic keys
  go to whatever is frontmost when no Magpie panel consumes them — check the
  log for "chooser shown" before sending letters.

## session: cockpit tools round two (audio, chat, URL scheme)

- Letters now: C clipboard, E emoji, D dictate, X capture, L launch (apps), S
  search, M math, A audio, T talk (Claude chat). Earlier note saying Apps = A is
  superseded.
- GOTCHA (permissions): under a terminal launch, TCC attributes Magpie to the
  terminal (responsible process), so `AX trusted=true` from a terminal-launched
  binary proves nothing about Magpie's own grant. Only a LaunchServices launch
  (`open Magpie.app`) tests the real grant. On 2026-09-09 the real grant was
  missing (stale row from the pre-certificate build); `tccutil reset
  Accessibility local.magpie` + fresh prompt fixed it. Signing identity was
  stable throughout (designated requirement = identifier + leaf cert hash).
- GOTCHA: `NSLog("... \(string)")` treats `%` in the string as format
  specifiers — percent-encoded URLs come out garbled. Use `NSLog("%@", s)`.
- GOTCHA: `screencapture -l <id>` (and any activity that gives the frontmost
  app a click) makes a non-activating key panel resign key. Irrelevant now
  that the chooser reads keys from the tap.
- GOTCHA (testing): never open the chooser with synthetic ⌘Space while the
  user is at the keyboard — it eats their next keystroke as a tool letter.
  Use `open "magpie://<tool>"` (toggles) and `magpie://chat?ask=...` instead;
  zero keystrokes.
- Chat: `claude -p … --output-format stream-json --verbose
  --include-partial-messages --resume <id>`; init event carries session_id;
  text arrives as stream_event/content_block_delta/text_delta; `result` ends
  the turn with total_cost_usd. Working dir `~/Magpie` with seeded CLAUDE.md.
- `NSMetadataQueryIndexedLocalComputerScope` → 0 results; plain
  `NSMetadataQueryLocalComputerScope` works. Search waits for 2 chars.
- Log file: `~/Library/Logs/Magpie/magpie.log` (stderr redirected when not a TTY).
